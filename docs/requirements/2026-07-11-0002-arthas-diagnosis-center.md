# Arthas 诊断中心需求

## 状态

已设计，待实现（V1.5）。

## 背景

Arthas 是阿里巴巴开源的 Java 诊断工具，支持线上 JVM 实时监控和故障排查。MagicOps 将 Arthas 能力集成到平台中，使运维工程师和安全审计员可以在受控环境下对生产 Java 应用进行诊断，而无需直接登录服务器。

## 目标

- 提供基于 Web 的 Arthas 诊断入口，无需 SSH 登录目标服务器；
- 所有诊断操作必须受权限控制、可审计、可追溯；
- 诊断命令必须经过模板化约束，禁止自由执行任意 Arthas 命令；
- 诊断会话必须有超时和并发限制；
- 诊断输出必须脱敏后存储和展示。

## 用户角色

| 角色 | 诊断权限 |
|---|---|
| 运维人员 | 创建诊断会话、执行已审批命令模板、查看输出 |
| 平台管理员 | 管理命令模板、配置 Tunnel Server、全局审计 |
| 安全审计员 | 查看诊断审计记录、导出报告 |
| 其他角色 | 无诊断权限 |

## 核心功能

### 诊断会话管理

- 选择目标应用实例（IP + 端口）；
- 创建诊断会话（关联用户、目标、时间窗口）；
- 会话超时自动关闭（默认 30 分钟）；
- 并发会话限制（每实例最多 1 个活跃会话）；
- 会话结束后输出归档。

### 诊断命令模板

- 预定义命令模板（thread、dashboard、trace、watch、jad 等）；
- 模板带参数约束（正则白名单）；
- 高风险命令需要额外审批（如 retransform、redefine、stop）；
- 禁止自由输入任意 Arthas 命令；
- 命令模板版本管理和审计。

### 安全约束

- 诊断不得影响生产业务（只读命令优先）；
- 禁止执行可能修改 JVM 状态的命令（除非显式审批）；
- Tunnel Server 不得暴露到公网；
- 诊断操作全部审计（命令、参数、输出摘要、操作人、时间）；
- 敏感信息（密码、密钥、token）在输出中自动脱敏。

### 输出与报告

- 实时流式输出（WebSocket）；
- 命令执行结果存储（脱敏后）；
- 诊断报告生成（会话摘要 + 命令历史 + 关键发现）；
- 报告可导出为 PDF/HTML。

## 验收标准

- 运维人员可以通过 Web 界面对目标应用创建诊断会话；
- 只能执行已审批的命令模板，自由命令被拒绝；
- 所有诊断操作有完整审计记录；
- 会话超时后自动关闭并归档；
- 敏感信息在输出中被脱敏。

## 非功能需求

- 诊断会话延迟 < 2 秒（命令下发到输出开始）；
- 支持同时管理 50 个目标应用的诊断配置；
- 审计记录保留 180 天；
- Tunnel Server 支持内网部署。
