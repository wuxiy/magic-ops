## Console 前端 UI 审核与修复(impeccable audit → 修复)

### 背景

对 `magicops-console/frontend` 做代码级 UI 技术审核(可访问性 / 性能 / 响应式 / 主题化 / 反模式五维度),得分 12/20(Acceptable)。审核同时发现用户管理页前后端契约严重错位。本切片按审核行动列表完成修复。

### 完成内容

- 新增 `PRODUCT.md`(register=product、用户、品牌个性、设计原则)与 `DESIGN.md`(视觉系统文档)。
- 新增 `src/styles/index.css`:共享布局类(`.page-title` / `.card-header` / `.pagination-wrap`),placeholder 色覆盖为 `#6f7379`(满足 WCAG AA 4.5:1)。
- `api/client.ts`:响应拦截器统一弹错误提示(优先后端 `{ error }` 字段,网络异常有专门文案),支持 `skipErrorMessage` 豁免;401 跳登录页并保留 `redirect` 回跳参数。
- 静默失败修复:5 个列表页请求失败不再清空表格冒充"无数据",保留当前数据 + 拦截器统一报错。
- 登录页:加 `aria-label`、去掉 `@keyup.enter` 重复提交(按钮改 `native-type="submit"` 单一提交路径)、加 loading 重入保护、卡宽改 `min(400px, calc(100vw - 32px))`。
- 布局壳:侧边栏激活色 `#409eff` → `#79bbff`(对比度 3.8:1 → ≥4.5:1);顶栏/内容区硬编码 hex 换 Element Plus token。
- 5 个列表页:页面标题 `<span>` → `<h1 class="page-title">`,删除重复的 scoped 布局样式。
- 用户管理页对齐后端真实契约:
  - 假分页修复:后端 `/api/users` 返回全量数组,改为前端分页(切片 + total 取自全量长度),原来第二页起数据不可达。
  - 前端 `User` 类型与后端 `UserResponse` 不一致(无 role/permissions/updatedAt),拆分为 `ManagedUser`(列表)与 `CurrentUser`(会话),auth store 同步重写。
  - 角色分配原调用不存在的 `PUT /users/{id}/role`,改为真实端点 `POST /users/{id}/roles {roleName}`;角色选项从硬编码改为 `GET /api/roles` 动态加载;对话框内展示当前角色并过滤已拥有角色。
  - 新建用户对话框:移除后端不接受的 role 字段(原为静默无效的假功能),加邮箱字段;`required` 星号补上真实校验规则(用户名/密码必填)。

### 验证结果

- `npm run type-check`(vue-tsc):通过,零错误。
- `npm run build`:通过,产物输出至 `magicops-console/src/main/resources/static/console/`。主 bundle ~1.2 MB(全量引入 Element Plus,已记录为待评估项)。
- 未做浏览器运行时验证(未启动 dev server 截图),对比度数值为计算值。

### 技术决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 用户列表分页 | 前端分页 | 后端返回全量数组,不改 API 契约(契约变更需 plan-first) |
| 角色 UI | 对话框内"当前角色 + 新增分配" | 后端角色为一对多且只有分配端点,无移除端点 |
| 错误提示位置 | axios 拦截器统一 | 消除 6 处静默 catch 的系统性问题 |
| 表格操作按钮 | 保持 `size="small"` | 桌面内网工具密度优先(product register 许可) |
| 侧边栏深色 | 保留 `#304156` 系 | 有意的深色导航区,已记录进 DESIGN.md |

### 遗留问题

- 后端无"移除角色"端点,前端只能分配不能回收 —— 需要后端切片,属认证授权保护区,须 plan-first。
- `LoginResponse` / `KeyEntry` 类型定义与后端不符但当前无调用方,暂未清理。
- Element Plus 按需引入(减小 bundle)未做。
- 表格加载态为 `v-loading` 遮罩,骨架屏未采用。

## Console 前端:Element Plus 按需引入

### 完成内容

- 安装 `unplugin-vue-components@32.1.0`(devDependency),`vite.config.ts` 配置 `ElementPlusResolver({ directives: true })`,模板组件与 `v-loading` 指令自动按需引入,`src/components.d.ts` 自动生成(已加入 `.gitignore`)。
- `main.ts` 移除 `app.use(ElementPlus)` 全量注册、全量 `index.css`、全量图标全局注册;`ElMessage` / `ElMessageBox` 样式改为手动按需引入。locale 由 `App.vue` 已有的 `el-config-provider` 承接。
- 修复按需引入后 `components.d.ts` 严格插槽类型暴露的 4 处类型错误(表格操作列 row 断言、`el-tag` type 字面量联合)。

### 验证结果

- `npm run type-check`:通过。
- `npm run build`:通过。入口 chunk **1,241 kB → 227 kB(gzip 403 kB → 87 kB,-78%)**;组件 CSS 按 chunk 拆分,`:root` CSS 变量随 `base.css` 正常输出(已 grep 验证 placeholder 覆盖生效)。
- 构建无 "Failed to resolve component" 警告,全量图标已确认无模板隐式依赖。

### 技术决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 按需方案 | unplugin-vue-components | Element Plus 官方推荐,免手动注册 |
| JS API 样式 | main.ts 手动引入 message/message-box 样式 | 比 unplugin-auto-import 少一层魔法,显式可控 |
| 图标 | 视图内显式 import(已有写法) | 移除全局注册后 ~300 个未用图标不再打包 |
