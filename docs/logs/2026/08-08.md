## 切片 31 实现：身份与追责

### 完成内容

- 新增 `CurrentActor`（console/security）：从 SecurityContext 读取已认证用户名，未认证回退 `system`。
- `ScriptController` 五处硬编码 actor（`"system"`/`"reviewer"`/`"publisher"`）全部替换为 `CurrentActor.username()`：创建、版本固化、提交、审批、发布。发布包 manifest 的 publishedBy 自此为真实操作人，Runtime 侧查询/修复审计的 operator 随之落地。
- `UserController` 角色授予人强制取登录身份（忽略客户端 grantedBy 传值）；新增 `DELETE /api/users/{id}/roles/{roleId}` 角色回收端点（user:manage 权限，关键审计）。
- `UserService` 注入 AuditService：`assignRole` 落 ROLE_ASSIGNED 关键审计，新增 `revokeRole` 落 ROLE_REVOKED 关键审计；`AuditEventType` 新增两枚举。
- 提交人/审批人分离：`ScriptLifecycleService.decide()` 校验决策人 ≠ 审批记录提交人，违反抛 `ApprovalSeparationException`，`GlobalExceptionHandler` 映射 403。
- `DataInitializer` profile 约束：prod 仅当显式提供 `MAGICOPS_ADMIN_PASSWORD`（经 Spring relaxed binding 映射 `magicops.admin.password`）时初始化 admin，永不创建 developer/approver 测试账号；非 prod 维持三角色初始化。
- 附带修复既有缺陷：`GlobalExceptionHandler` 的通用 Exception 处理器吞掉 `AccessDeniedException` 导致 RBAC 越权返回 500 而非 403，新增安全异常重抛处理器。

### 关键设计决策

- actor 传递不引入线程上下文容器，直接在 Controller 层从 SecurityContext 取值传入服务层，保持服务层签名显式携带 operator（利于测试与审计追踪）。
- 分离校验放在 `decide()` 加载审批记录之后、状态变更之前，违规不产生任何副作用。
- E2E 自审自批负例由 admin 执行（admin 同时持有提交与审批权限），确保 403 来自分离规则而非 RBAC 拒绝。

## 切片 32 实现：密钥与凭据固化

### 完成内容

- `KeyProvider` 重构为配置驱动：KeyStore（JDK 标准 `java.security.KeyStore`，JKS/PKCS12）→ 环境变量 → 临时密钥三级装配；`magicops.sign.allow-ephemeral-keys` 在两应用 prod 配置置 false，缺密钥启动即失败（fail-fast），错误信息附两种修复路径。KeyStore 模式下全部别名进入信任集，支持密钥轮换过渡期验签。
- `KeyStoreKeyProvider` 增加类型参数（JKS/PKCS12），由 `KeyProvider` 组合复用；保留双构造器兼容。
- 新增 `PushSecretAuthenticationFilter`（`OncePerRequestFilter`，注册在 Runtime SecurityFilterChain 的 `UsernamePasswordAuthenticationFilter` 之前）：仅拦截 `POST /api/packages`；密钥已配置时强制 `X-MagicOps-Push-Secret` 头匹配，否则 401；未配置密钥且 prod profile 时 fail-closed 401；非 prod 放行并告警。
- 请求头/路径常量收敛到 core 模块 `PushProtocol`，Console 与 Runtime 共享，避免跨应用模块依赖。
- `PushService` 注入 `magicops.runtime.push-secret`，非空时推送携带共享密钥头；未配置时告警。
- Runtime prod Basic 凭据外置：`${RUNTIME_PASSWORD:?}` fail-fast。
- 凭据出库：根 `docker-compose.yml` 硬编码密码全部改为 `${VAR:?}` 必填引用并清理无人消费的 `CONSOLE_ADMIN_PASSWORD`；新增根 `.env.example` 与 `deploy/.env.example`；`deploy/.env` 本就不在 git 跟踪内，保留本地。

### 关键设计决策

- 坚持"有开源/标准组件就不自研"：密钥持久化用 JDK KeyStore，推送认证用 Spring Security 过滤器扩展点，fail-fast 用 Spring Boot `${VAR:?}` 占位符与 Bean 初始化异常，未新增任何第三方依赖。
- fail-closed 语义分环境：prod 未配置推送密钥一律 401；dev 放行并告警，保证本地与 E2E 流程不被打断。
- 过滤器仅作用于收包 POST，`GET /api/packages/active` 状态查询与其他端点不受影响。
