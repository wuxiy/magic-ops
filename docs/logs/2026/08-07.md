## 切片 30 实现：SQL Guard 与数据修复强制化

### 完成内容

- `SqlGuardService` 从字符串前缀匹配重构为 JSQLParser 4.9 解析树方案（新增根依赖管理与 `magicops-sql-guard` 模块依赖），新增 `parseSingleStatement`、`validateForRepair`（AST 级 WHERE 检查）、`tablesIn`（排除 CTE 名、去重排序）、`targetTables`、占位符规范化。
- `PackageBuildService`（console）打包时生成治理凭据：APPROVED 审批凭据写入 metadata `approvals`，SQL 引用表清单写入 `datasourcePermissions`，两者随包签名；无审批、审批被拒、SQL 不可解析均拒绝打包。
- `RepairExecutionService`（runtime）执行链增加审批凭据校验、执行内容与包内脚本 contentHash 绑定校验、表级白名单校验；执行改为事务化，影响行数超过 `MAX_AFFECTED_ROWS=100` 即回滚并落阻断审计。
- `QueryExecutionService`（runtime）增加表级白名单校验，遗留包（无授权声明）告警放行。
- `DynamicDataSourceManager` 新增 `executeUpdateInTransaction`（事务执行 + 行数上限回滚）。
- `DryRunService` 切换到解析器分类与校验。
- 修复 Runtime 自切片 9-11 以来的启动失败：共享 audit 模块的 `AuditController` 硬依赖 JPA 仓储，被 Runtime 宽扫描捕获导致 bean 装配失败（既有回归，非本切片引入）。`RuntimeApplication` 扫描时排除该控制器，审计维持 `AuditService` 内存回退；完整审计持久化由切片 33 收口后移除排除项。

### 关键设计决策

- 审批强制不走 Runtime 回查 Console 数据库，而是把审批凭据嵌入发布包 metadata 并由签名保护（metadataHash + 整体签名），Runtime 只做验签后校验，保持 Runtime 单向依赖。
- 执行内容与已审批脚本的绑定通过 contentHash 比对实现，防止"审批一套、执行另一套"。
- 校验顺序刻意保持 DryRun、SQL Guard、审批、内容绑定、白名单、事务执行，使既有测试的错误消息语义不变。
