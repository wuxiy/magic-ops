# 应用开发工作流

## 目的

本文件定义 MagicOps 的轻量级 AI 辅助开发工作流。

该工作流用于避免三类常见失败：

- 宽泛需求堆砌变成 demo 级实现；
- 安全关键平台规则只存在于聊天里；
- 产品、架构和执行记录混成一篇过期文档。

## 默认流程

非平凡工作默认流程：

1. 读取 `docs/context/`；
2. 选择工作时检查 `docs/backlog/`；
3. 将原始输入记录到 `docs/input/`；
4. 在 `docs/requirements/` 中整理可实现需求；
5. 在 `docs/design/` 中更新稳定产品行为；
6. 在 `docs/architecture/` 中更新稳定技术结构；
7. 路由任务并选择可复用方法；
8. 触发计划条件时，在 `docs/plans/` 中创建计划；
9. 实现前审查计划；
10. 实现最小完整切片；
11. 用真实命令验证；
12. 对已创建计划执行关闭审查；
13. 必要时记录日志、测试记录、缺陷记录或经验沉淀。

## 计划触发条件

当工作改变以下内容时，创建计划：

- API 契约；
- 数据库/模型形态；
- 认证或权限；
- 审批、签名、Runtime 发布或部署；
- 外部集成；
- 数据修复或 SQL Guard 行为；
- 审计可靠性或脱敏行为；
- 多模块或跨切面架构。

## 无计划路径

只有在以下条件同时满足时，才可走无计划路径：

- 控制该任务的 owner doc 清楚；
- 不触及保护区；
- 验证命令真实存在，或工作仅限文档；
- 最终 diff 可以直接对照请求冷读。

## 验证

一旦 `docs/context/project-context.md` 中的真实验证命令存在，就运行它们。

在命令建立前，纯文档变更可以通过以下方式验证：

- 检查链接和路由一致性；
- 检查事实源冲突；
- 检查 `git status`。

项目脚手架缺失时，不要声称构建或测试成功。
