# 角色与权限

## 角色

| 角色 | 职责 |
|---|---|
| 平台管理员 | 用户、角色、系统配置、密钥配置和全局审计。 |
| 项目管理员 | 项目配置、环境配置、数据源配置和成员管理。 |
| 开发人员 | 草稿编辑、测试调试、提交审批。 |
| 审批人员 | 审核脚本、批准发布、批准高风险操作。 |
| 运维人员 | 执行受控任务、查看日志、第二阶段创建诊断会话。 |
| 安全审计员 | 查看审计记录、导出报告、检查权限和发布记录。 |
| 只读观察者 | 查看 API、日志和报告，无执行权限。 |

## 权限维度

权限必须覆盖：

- 项目；
- 环境；
- API/script；
- 数据源；
- 表/资源；
- SQL 操作类型；
- HTTP 目标系统；
- HTTP 目标路径；
- key reference；
- 发布；
- 回滚；
- 审计查询；
- 第二阶段诊断命令。

## 第一阶段权限规则

- 生产 Runtime 执行不能只依赖 Console 角色校验；Runtime 必须验证已签名包元数据和资源权限。
- 开发人员可以创建和调试草稿，但不能直接发布到生产。
- 审批人员不能绕过签名或 Runtime 验签。
- 运维人员只能执行已审批、已发布的修复路径。
- 安全审计员可以查看记录，但不能修改脚本、审批、密钥或 Runtime 状态。

## 受保护操作

以下操作受保护：

- 批准高风险数据修复；
- 签名发布包；
- 推送发布包到生产 Runtime；
- 回滚生产发布包；
- 修改 key reference；
- 修改数据源权限；
- 注册或变更 HTTP 目标系统；
- 修改 SQL Guard 策略；
- 修改审计留存或脱敏行为。
