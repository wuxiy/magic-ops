# 应用概览

## 产品定位

MagicOps 是面向医院、卫健委、政务云和区域医疗项目的内网动态开发与集成运维平台。

它基于 `magic-api` fork，并在 magic-api 之上补强治理、安全、签名、审计和 Runtime 控制。

MagicOps 不用于替代标准 Java 工程化研发。它是面向需求变化快的内网交付和运维工作的受控补充。

## 核心产品形态

| 形态 | 目的 |
|---|---|
| Starter | 嵌入业务项目，提供 Runtime 执行能力。 |
| Console | 部署在管理网或运维网，负责编辑、调试、审批、签名、发布和审计查询。 |
| Gateway | 独立 Runtime 形态，用于内网系统集成和接口适配。 |
| Diagnosis Center | 第二阶段基于 Arthas 的 Java 诊断中心。 |

## 第一阶段产品焦点

第一阶段聚焦三个受控闭环：

1. 动态查询接口；
2. 受控数据修复；
3. HTTP 接口适配。

第一阶段同时建立共享治理闭环：

```text
Console edit/debug
  -> submit
  -> approve
  -> sign
  -> online push
  -> Runtime verify
  -> Runtime execute
  -> audit
```

## 主要用户

| 用户 | 诉求 |
|---|---|
| 项目开发 | 快速构建临时查询 API、数据核查和接口适配脚本。 |
| 实施工程师 | 现场联调、数据核查和接口验证。 |
| 运维工程师 | 查看执行日志、定位生产问题、执行受控修复任务。 |
| 技术负责人 | 审批高风险变更、控制发布风险、追踪执行历史。 |
| 安全审计员 | 审查审计、权限、发布和访问记录。 |

## 非目标用户

不要直接向以下用户开放 MagicOps：

- 普通业务用户；
- 没有 SQL、Java 或接口集成经验的用户；
- 未审批的第三方厂商账号；
- 未认证用户或公网用户。

## 适合使用

推荐：

- 临时查询和统计；
- 数据核查；
- 受控数据修复；
- 非核心接口适配；
- 外部系统集成和字段映射；
- 需要签名受控发布的应急响应。

谨慎使用：

- 医嘱核心流程；
- 医保结算；
- 费用核心流程；
- EMR 核心写入流程；
- 任何影响诊疗安全的关键业务逻辑。

禁止：

- 生产在线编辑；
- 高风险 SQL 绕过审批；
- 脚本访问任意 URL；
- 在脚本中硬编码密钥、密码或 token；
- 未审计的数据修复或 MQ 发送；
- 日志或审计记录中出现未脱敏患者敏感数据；
- 将原生 Arthas 控制台直接暴露给普通用户。

## 成功指标

| 指标 | 目标 |
|---|---|
| 临时 API 交付时间 | 从天级降到小时级 |
| 数据修复可追溯性 | 100% 审批和审计覆盖 |
| 生产在线编辑 | 0 |
| 高风险 SQL 路径 | 100% 经过 SQL Guard |
| Runtime 执行审计 | 动态脚本执行 100% 覆盖 |
| Runtime 签名发布 | 生产脚本 100% 签名 |
| 诊断记录覆盖 | 第二阶段关键诊断会话归档 |
